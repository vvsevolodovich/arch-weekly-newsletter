## [Kimi K3: Open Frontier Intelligence](https://www.kimi.com/blog/kimi-k3) 🤓

Moonshot AI's Kimi K3 is the first open-weight model to cross the 3-trillion-parameter class, activating 16 of 896 experts per token (104B active params) via Stable LatentMoE, which allocates experts from router-score quantiles rather than heuristic balancing coefficients — a design choice that eliminates the sensitivity to manually-tuned hyperparameters endemic to large MoE training. The architecture introduces Kimi Delta Attention (KDA), a hybrid linear/full-attention mechanism delivering 6.3× faster decoding on long-context inputs, backed by FlashKDA (1.72–2.22× faster prefill on NVIDIA H20 vs. the flash-linear-attention baseline), MoonEP (an expert-parallel communication library for imbalanced routing), and AgentEnv (the distributed RL environment used in training) — all released open-source alongside the model weights on July 26. MXFP4 weights with MXFP8 activations, with quantization-aware training applied from the supervised fine-tuning stage onward, make the model deployable on non-HBM hardware without retraining. #ai #llm #architecture #engineering

## [Federating clusters for zero-downtime Kubernetes](https://www.cncf.io/blog/2026/07/27/federating-clusters-for-zero-downtime-kubernetes/) 👨‍💼

Linkerd's multicluster extension offers three distinct modes — federation (single load-balanced endpoint spanning all clusters, automatic failover with no application changes), flat mirroring (direct pod-to-pod routing via VPC peering, bypassing gateways entirely), and gateway mirroring (cross-cluster reach via ingress/egress gateways, works over the public internet) — with the expectation that production platforms combine modes across different services rather than committing to one. Each cluster runs a fully independent control plane with no global registry; inter-cluster links are mTLS watch relationships against the target cluster's Kubernetes API, so the failure domain is each cluster and its links, not a shared control path. Joining a federation requires a single kubectl label; when a cluster fails, surviving pods absorb traffic with zero configuration changes. #devops #cloud #distributed #architecture
