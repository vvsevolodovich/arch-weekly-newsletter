## [Cloudflare OS: an open platform for agents, apps, and work](https://blog.cloudflare.com/cloudflare-os/) 🤓

Cloudflare OS solves the agent credential problem at its root with Gatekeepers — per-service Worker processes that issue scoped capability objects to agents rather than ever exposing raw API keys, OAuth tokens, or database credentials. Every user runs their own isolated gadget instance of each app (no shared SaaS state), and every data access an agent makes is recorded and attached to the artifact it produces, so downstream readers are checked against the underlying data's ACL before they can see the output. The platform is self-hostable under Apache 2.0, runs entirely on Cloudflare Workers, and was open-sourced as part of Agents Week on August 5, 2026. #ai #architecture #security #engineering

## [Scaling Exact COUNT(DISTINCT) for High-Cardinality Non-Rollup Metrics in Distributed Data Pipelines](https://www.uber.com/us/en/blog/scaling-exact-count/) 🤓

Monthly active users, quarterly retention, and cross-window engagement are non-rollup metrics — they cannot be derived from pre-aggregates and require tracking up to 3.6 billion UUID-valued identifiers simultaneously in memory. RoaringBitmap is the industry standard here, but at Uber's cardinality the JVM's Integer.MAX_VALUE (~2 GB) array bound triggers OOM; the fix is a chunked aggregation buffer that partitions bitmap state into segments each safely under that limit and recombines at output time. Since deployment across 75 metric families spanning Mobility, Delivery, and Platform verticals, zero OOM failures have been observed. #distributed #engineering #softwareengineering

## [Indexing the Data Lake for Online Point Queries](https://engineering.atspotify.com/2026/7/indexing-the-data-lake-for-online-point-queries) 🤓

At Spotify, exabytes live in GCS while petabytes are replicated into Bigtable purely for online point-query access — RAP (Random Access Parquet) collapses that split by building an external key-to-location index over the existing Parquet files, with no second copy of the data and no pipeline rewrites required. GCS and S3 Express One Zone now deliver single-digit millisecond storage latency, but the real bottleneck is query engine overhead: Trino and BigQuery add seconds of scheduling even for a single-row lookup, which RAP replaces with a targeted ranged read that resolves to the exact byte range in effectively constant time via cached file metadata. The same files BigQuery scans for weekly reports also answer a per-user point query at roughly the cost of a single storage read. #db #architecture #engineering
