## [PQC in Plaintext: Google Cloud's post-quantum cryptography roadmap](https://cloud.google.com/blog/products/identity-security/pqc-in-plaintext-google-clouds-post-quantum-cryptography-roadmap) 🤓

Google Cloud's post-quantum migration work is split across three delivery domains — SNDL risk elimination by end of 2027, integrity and non-repudiation by 2028, and cryptographic key management foundations by 2028 — with full platform coverage targeted for 2029 and legacy algorithm deprecation expected between 2030–2035. ML-KEM hybrid key exchange (X25519MLKEM768) is already live on all google.com and *.googleapis.com endpoints and all Application and proxy load balancers; Cloud KMS already supports all three NIST PQC standards (ML-KEM, ML-DSA, SLH-DSA) for customer-managed keys. The shared responsibility model is the critical planning input for enterprise teams: Google secures the infrastructure layer, but customers own updating their own SDKs, renegotiating PQC handshakes, reconfiguring certificate authorities, and migrating their own application-layer cryptography — and that work is non-trivial at any scale. #security #architecture #cloud #engineering

## [Accelerate PostgreSQL migrations using Gemini in Database Migration Service](https://cloud.google.com/blog/products/databases/accelerate-postgresql-migrations-with-gemini-in-dms) 👨‍💼

Legacy stored procedure migration — the friction that has blocked Oracle-to-PostgreSQL moves for decades — now has an AI-accelerated path in Google Cloud's Database Migration Service: a deterministic compiler handles 1:1 syntax mappings (NVL→COALESCE, DECODE→CASE, exception-handling rewrites) while Gemini synthesizes complex procedural blocks using full schema context — cross-procedure call graphs, data type relationships, view dependencies — rather than isolated code snippets. Google claims this collapses stored procedure conversion timelines from months to days, and the conversion workflow stays entirely within IAM-governed Cloud project boundaries with mandatory staging deployment to Cloud SQL or AlloyDB before production cutover. The DFS-based call graph analysis that propagates result-set counts up the procedure hierarchy is the technical detail worth noting: a stored procedure that calls another that calls another must be fully traversed before the target translation target (PROCEDURE vs. FUNCTION with SETOF refcursor) can be determined. #db #migration #ai #engineering

## [Introducing Developer Device Platform for agentic mobile app development](https://cloud.google.com/blog/topics/developers-practitioners/announcing-developer-device-platform-on-google-cloud) 👨‍💼

Google Cloud's Developer Device Platform enters public preview as the first cloud device-testing infrastructure designed around agentic workflows: the Device Run API fans tests across hundreds of real or virtual devices simultaneously using smart sharding, while smart auto-retry targets specific failing tests rather than rerunning full suites, and a dedicated agent skill lets AI coding agents execute multi-step user journeys — spot visual artifacts, validate hardware-specific behavior, analyze on-device chip performance — without human supervision. The platform supersedes Firebase Test Lab and prices per active testing minute with separate rates for emulators vs. physical hardware, integrating natively with Android Studio, Android CLI, and CI/CD pipelines. The structural shift worth noting for architecture teams: the same MCP tool interface exposed to external coding agents (Claude, Cursor, Codex) is the same interface used by DDP's own agent skill, creating a unified testing plane accessible from both the platform's built-in AI and any MCP-compatible agent. #devops #ai #cloud #engineering
