## [Minimize idle accelerators: Native RL job interleaving with co-operative time-slicing in llm-d](https://cloud.google.com/blog/products/containers-kubernetes/introducing-co-operative-time-slicing-for-rl-in-llm-d) 🤓

Distributed RL post-training leaves 40–60% of GPU accelerators idle — synchronous trainers hold CUDA context and device memory locks while waiting for sampler batches, and even async pipelines stall at the trajectory handoff boundary. Co-operative time-slicing in llm-d treats discrete RL phases (rollout sampling, gradient training) as schedulable entities: a gRPC `acquire()`/`yield()` client API marks phase boundaries, a cluster-scoped orchestrator manages per-group lock queues, and a node-level Snapshot Agent (privileged DaemonSet) serializes GPU device state to host DRAM before restoring the next job's context. The approach raises aggregate accelerator duty cycles from ~40% baseline to 70% with no impact on model convergence or accuracy. #ai #cloud #architecture #engineering

## [Open Knowledge format v0.2 tackles agentic trust](https://cloud.google.com/blog/products/data-analytics/okf-v0-2-adds-trust-signals) 👨‍💼

Multi-agent systems that write and read from shared knowledge corpora have no standard way to signal how much to trust a particular piece of data — OKF v0.2 adds five provenance fields (`sources`, `generated`, `verified`, `stale_after`, `status`) and a new Attested Computation concept type that ensures metrics were produced by a pre-approved, deterministic SQL execution path rather than an LLM generating a value. Trust tiers (unverified / machine-confirmed / human-reviewed) are encoded as advisory signals rather than scores, keeping the format minimally opinionated while allowing consumers to apply their own filters; the spec is backward-compatible with v0.1 and all new fields are opt-in, making absence itself meaningful. The attester pattern — canonical SQL comparison rejecting any deviation from the sanctioned query — provides a deterministic, non-LLM guard against hallucinated numbers in agentic reporting pipelines. #ai #architecture #engineering #distributed

## [Apache DataFusion Ballista 54.0.0 Released](https://datafusion.apache.org/blog/output/2026/07/12/datafusion-ballista-54.0.0/) 🤓

Apache DataFusion Ballista 54.0.0 ships 171 commits from 11 contributors and closes the longest-standing operational gap in the distributed query engine: a TPC-H distributed plan-stability test suite with documented golden files and a CI-enforced regeneration process now verifies that Ballista produces consistent distributed plans across releases — a prerequisite for treating cluster execution as production-grade. This is also the first release to publish pre-built Python wheels to PyPI, removing the Rust toolchain requirement that had blocked adoption outside Rust-native environments. Built on DataFusion 54.0.0, the release advances Adaptive Query Execution and makes Ballista viable for teams running Python data workloads across Kubernetes clusters without compiling from source. #db #distributed #softwareengineering #engineering
