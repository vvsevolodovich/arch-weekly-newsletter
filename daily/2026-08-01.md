## [Paging Through a Parquet File in DuckDB: file_row_number or OFFSET?](https://rusty.today/blog/paging-parquet-duckdb-file-row-number-vs-offset/) 🤓

LIMIT/OFFSET pagination on Parquet files in DuckDB is not just slow — it can silently return wrong rows, because DuckDB's columnar scan does not guarantee stable row ordering across queries when row groups are involved. DuckDB's `read_parquet` exposes a `file_row_number` virtual column giving each row's physical position, enabling range-based pagination that skips entire row groups rather than scanning and discarding them: 2.53× faster on a 163-row-group test file. Any paging API backed by Parquet storage should treat OFFSET as a correctness bug, not just a performance concern. #db #engineering #architecture

## [2x, Not 10x: Coding with LLMs in 2026](https://obryant.dev/p/2x-not-10x/) 👨‍💼

The 2026 LLM productivity plateau has a structural explanation: reliability, not raw capability, was the binding constraint — adoption accelerated the moment models became dependable enough to run inside automated feedback loops, not when they became smarter. Further scaling delivers diminishing engineering returns because "stair-height" (can the model reliably complete a task at all?) matters far more than extra reach, and most software tasks already clear the current reliability threshold. The realistic near-term gain from better models alone is 2×, not 10×; the actual 10× gains require re-architecting workflows, CI/CD pipelines, and development culture around models that already exist today. #ai #llm #softwareengineering #engineering
