## [PostgreSQL's MVCC is bad. So is everyone else's.](https://boringsql.com/posts/mvcc-bad-bad/) 🤓

PostgreSQL's MVCC model stores old row versions in the heap alongside live data, causing table bloat and write amplification that every DBA eventually fights with autovacuum. The post applies a four-question framework — where old versions live, which direction the version chain runs, what indexes point at, and who performs cleanup — across Oracle, InnoDB, SQL Server, MongoDB, LSM stores, and etcd, revealing that every storage engine trades these costs differently rather than solving them. At PGConf.DE 2026, Álvaro Herrera flagged zheap as the first in-core pluggable table access method targeting PostgreSQL 2029; REPACK CONCURRENTLY is the nearer-term mitigation aimed at PostgreSQL 19. #db #architecture #engineering

## [Massively parallel Postgres backups](https://planetscale.com/blog/massively-parallel-postgres-backups) 🤓

PlanetScale backs up petabyte-scale sharded Postgres — 768 servers, over a petabyte of data — in hours at sustained rates exceeding 50 GB/s by combining filesystem snapshots with WAL replay rather than logical dump. Backup-specific nodes pull from object storage with massive parallelism; a custom Kubernetes operator orchestrates the entire lifecycle without touching production query paths. The architecture makes backup throughput a function of object storage bandwidth rather than database node count, which scales independently of the shard topology. #db #distributed #architecture #engineering

## [Amazon CloudWatch announces managed Prometheus collectors](https://aws.amazon.com/about-aws/whats-new/2026/07/cloudwatch-managed-collectors/) 👨‍💼

AWS now manages the OpenTelemetry Collector layer for EKS (Kubernetes service discovery), EC2 (direct instance scraping), ECS (DNS-based via AWS Cloud Map), MSK, and OpenSearch Service, eliminating the operational burden of self-hosted collector deployments. Scraped metrics arrive in OpenTelemetry format and are queryable with PromQL alongside AWS-vended metrics in the same CloudWatch workspace, making the managed path a drop-in for teams already using Amazon Managed Service for Prometheus. Pricing is per collector-hour; available in all CloudWatch OTLP endpoint regions except AP (New Zealand). #devops #cloud #architecture
